# Бот поиска кодов ошибок банкомата (webhook-версия)

Вариант для хостинга с «живым URL» (Ample Computer, Vercel, Render и т.п.).
Процесс не нужно держать включённым постоянно — Telegram сам присылает
обновления HTTP-запросом на `/webhook`.

## Файлы

- `app.py` — FastAPI-приложение с логикой бота
- `error_codes.json` — база кодов
- `schemes.py`, `schemes.json`, `schemes/` — схемы устройств, координаты датчиков (перенесены из приложения ATM Code Lookup)
- `requirements.txt` — зависимости
- `set_webhook.py` — одноразовый скрипт регистрации адреса в Telegram

## Деплой

1. Задеплоить `app.py` + `error_codes.json` + `requirements.txt` на хостинг,
   запуск командой вроде:
   ```
   uvicorn app:app --host 0.0.0.0 --port $PORT
   ```
2. В переменных окружения сервиса задать `BOT_TOKEN` (как секрет, не в коде).
3. После получения публичного URL сервиса — один раз выполнить:
   ```bash
   export BOT_TOKEN="токен"
   python set_webhook.py https://<твой-адрес>/webhook
   ```
4. Готово — пиши боту в Telegram.

## Важно про токен

Токен даёт полный контроль над ботом. Не коммить его в репозиторий и не
записывай в файлы проекта — только как переменную окружения на хостинге.

## Как бот понимает коды

- Можно присылать несколько кодов в одном сообщении: `-1335 -1334`.
- Понимает разные минусы (`−`, `–`, `—`), пробел после минуса, ведущие нули (`008` = `08`) и текст вокруг кода (`код 1335.`).
- Если в GRG есть код и с минусом, и без, на положительный ввод показываются оба; когда знак не совпал с введённым, это отмечается в ответе.
- В группах бот отвечает только если нашёл код, а «не найден» пишет лишь в личке.

## Меню выбора банкомата

`/menu` (и `/start`) показывает кнопки, как в приложении: **GRG** или **Wincor** → **CCDM (кеш-ин)** / **CMD-V4 (кеш-аут)**, плюс «Все базы сразу». После выбора код ищется только в базе этого устройства.

Выбор запоминается для каждого пользователя в каждом чате, если подключён Upstash Redis (бесплатный план). Бот берёт адрес и токен из переменных `KV_REST_API_URL` / `KV_REST_API_TOKEN` (их создаёт интеграция в Vercel) или `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`.

Подключение: Vercel → проект → **Storage** → **Create Database** → **Upstash for Redis** (план Free) → **Connect** к проекту → **Redeploy**.

Без хранилища режим живёт в переписке: сообщения бота в режиме начинаются с «🏧 Банкомат: …» и просят ответить на них (force reply). Пока пользователь отвечает на сообщения бота, режим сохраняется; обычное сообщение без ответа ищет по всем базам.

## Подсказки и инлайн-режим

- Если в описании кода упомянут датчик (например, SF17 в GRG 25523 или VLS4 в CCDM 21), сразу после ответа бот присылает схему нужного устройства с отмеченным датчиком. Несколько датчиков с одной схемы отмечаются на одной картинке, всего не больше 4 схем на сообщение (`MAX_AUTO_SCHEMES`).
- Инлайн-режим: в любом чате `@имя_бота 1335`. Его нужно один раз включить в @BotFather: `/setinline` → выбрать бота → ввести подсказку, например «код ошибки».
- Меню команд (/menu, /sensor, /schemes, /guides, /clear, /help) бот ставит сам через `setMyCommands` при первом запросе после деплоя.

## Инструкции по настройке (/guides)

`/guides` открывает меню инструкций: NCR (установка ПО Aptra на SelfServ), CINEO (установка ProFlex) и GRG (настройка банкомата, NeoVideo, активация Windows). Внутри можно выбрать раздел, листать кнопками «Назад» и «Дальше», скриншоты приходят отдельными фото. Последняя кнопка в списке разделов, «📄 Вся инструкция целиком», предлагает выбор: **файлом** (исходный документ из `guides/files`, имена заданы в `FILES` в `guides.py`) или **текстом в чат**, то есть все разделы подряд со скриншотами. Если отправка не уложилась примерно в 40 секунд, бот присылает кнопку «Продолжить с раздела N».

Тексты лежат в `guides/<id>.md` (`#` — название, `##` — раздел, `[img: файл.jpg]` — картинка из `guides/img`). Чтобы добавить инструкцию, положи новый файл и допиши его id в `ORDER` в `guides.py`.

## Очистка истории

Кнопка «🧹 Очистить историю» в `/menu` (или команда `/clear`) после подтверждения удаляет переписку с ботом в личном чате. Telegram не отдаёт боту список сообщений, поэтому бот удаляет последние 1000 id подряд через `deleteMessages`. Сообщения старше 48 часов Telegram удалить не даёт. В группах очистка не работает.

## Схемы и датчики

- Название датчика (`SF01`, `VLS12`, `PES`, `Print head`…) или `/sensor SF01` — бот присылает схему устройства с отмеченным датчиком. Если датчик есть на нескольких схемах (например, CMD-V4 Horizontal и Vertical), придут все. Регистр, пробелы, `-`/`_` и русские буквы-двойники не важны.
- `/sensor` без названия — сначала выбор устройства (CCDM, CMD-V4, GRG, Recycler или «Всё сразу»), потом список его датчиков. Кнопка «« Назад» возвращает к выбору.
- `/schemes` — так же: выбор устройства, потом кнопки его схем (CCDM, CMD-V4, GRG: CRM9250/CAM8320/CDM8240, Recycler CRS 4060 FL) и «« Назад». Группы заданы в `DEVICE_GROUPS` в `app.py`.
- Recycler CRS 4060 FL (из `CRS_4060_Frontload.pdf`) разбит на три картинки: моторы и соленоиды, датчики головы, DM/кассета/BVM. Датчики с диапазоном вроде `TUB_PS1a-d` находятся и по `TUB_PS1b`, и по `TUB_PS1`.
- В группах датчик из обычного текста ищется, только если он написан заглавными.
